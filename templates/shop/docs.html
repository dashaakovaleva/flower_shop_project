О проекте

FloraIS — учебная информационная система управления цветочным магазином. Она объединяет учёт товаров, заказов, клиентов, поставок и историю продаж с модулем прогнозирования спроса на пиковые даты: 14 февраля, 23 февраля, 8 марта, 1 сентября и 5 октября.

Проект относится к блоку А «Информационные системы»: ядро — реляционная БД, ролевая модель, бизнес-логика заказа и интерфейсы, а прогноз — сервисный модуль поддержки решений.

Разграничение реализовано декоратором role_required для HTML-представлений и классами разрешений DRF для API. Клиент не может читать чужие заказы, менеджер не может менять справочники через админку без прав администратора.

Данные

Синтетический генератор создаёт 2 года обучения и 365-дневный отложенный год. Формула:

спрос = база × тренд × день_недели × месяц × праздничный_разгон × шум × акция

Праздничный разгон растёт за 7–14 дней до даты и достигает максимума в сам праздник. Третий год генерируется другим случайным потоком, с повышенным шумом, изменённым трендом и ослабленными праздничными коэффициентами — это имитация изменившихся рыночных условий. Модель его не видит при обучении.

Внешний реальный датасет data/real/cashier_data.csv (Германия, 2016–2020) используется как референс недельной и месячной сезонности. Он не участвует в обучении, но позволяет проверить правдоподобность синтетики через KS-тест и корреляцию профилей.

Прогнозная модель

Основная модель — SARIMAX(1,0,1)(1,0,1,7) с экзогенными признаками: день недели, ряды Фурье годовой сезонности, ramp-признаки за 10–14 дней до праздника, сам праздник и короткий хвост после него. Если SARIMAX не сходится, автоматически используется регуляризованная сезонная регрессия.

Прогноз строится на 7 дней вперёд. Для каждого товара сравниваются прогнозируемый спрос, текущий остаток и страховой запас 15%. Если остатка не хватает, создаётся рекомендация с приоритетом: критичный, высокий, средний или низкий.

Метрики и ошибки I/II рода

  • MAE — средняя абсолютная ошибка в штуках;
  • RMSE — сильнее штрафует крупные промахи;
  • MAPE — средняя относительная ошибка, %;
  • WAPE — устойчивая относительная ошибка при нулевых продажах;
  • Bias — систематическое смещение: перепрогноз или недопрогноз;
  • Coverage — доля фактов внутри 80% интервала.

Для классификации «высокий спрос / обычный день» используется порог 80-го перцентиля обучающей выборки. Ошибка I рода (FP) — модель предсказала пик, а его не было. Ошибка II рода (FN) — модель пропустила реальный пик. Отдельно считается матрица ошибок для сигналов дефицита на 7 дней: ложная закупка (FP) и пропущенный дефицит (FN).

Команды управления

python manage.py migrate
python manage.py bootstrap_demo          # всё сразу: справочники, данные, обучение
python manage.py seed_reference          # категории, товары, роли, клиенты
python manage.py generate_sales          # 2 года + отложенный год + CSV
python manage.py import_real_data        # внешний реальный датасет
python manage.py train_models --model sarimax
python manage.py make_forecast --horizon 7
python manage.py create_demo_orders
python manage.py export_metrics          # docs/metrics.json и CSV

Ограничения подхода

  • Модель не учитывает погоду, локальные мероприятия и действия конкурентов;
  • акции и разовые корпоративные заказы могут исказить прогноз;
  • для новых товаров без истории применяется усреднение по категории;
  • синтетика не заменяет реальную историю продаж, а служит стендом для проверки архитектуры и методики;
  • SQLite подходит для локального запуска, для нагрузки нужен PostgreSQL.
